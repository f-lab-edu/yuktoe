# Feature Specification: 분석 탭 — AI 채팅 (Analytics Chat)

## User Scenarios & Testing *(mandatory)*

분석 탭 하단의 AI 채팅은 보호자가 자기 아기에 대한 궁금증(잘 크고 있는지, 시기별 발달 체크, 우리 아기에게 통할 육아 팁)을 자연어로 묻고, **그 아기의 실제 기록 데이터와 월령을 근거로** 답을 받는 대화형 상담 창구다.

### User Story 1 — 내 아기 기록 기반 질문·답변 (Priority: P1)

기록을 남겨 온 보호자로서, 나는 "아기가 요즘 매일 새벽 5시에 깬다" 같은 고민을 자연어로 묻고, 우리 아기의 **개월수와 최근 기록**(수면·수유·기저귀 등)을 종합한 맞춤 답변을 받고 싶다. 일반론이 아니라 "낮잠을 많이 자서 / 첫 낮잠이 늦어서 / 마지막 수유량이 적어서 / 여름이라 해가 일찍 떠서" 처럼 우리 아기 상황에 부합하는 진단을 원하기 때문이다.

**Why this priority**: 채팅 feature 가 존재하는 근본 이유다. 기록 기반 맞춤 답변이 없으면 일반 챗봇과 다르지 않다. 이 스토리 하나만으로 "내 아기 데이터로 상담받는다" 는 독립적 가치를 전달하는 MVP 가 된다.

**Independent Test**: 최근 기록이 있는 아기를 선택해 분석 탭에서 질문을 입력·전송하고, 답변에 그 아기의 월령/기록에 부합하는 근거가 포함되는지(스트리밍으로 점진 표시) 확인하면 단독 검증 가능하다.

**Acceptance Scenarios**:

1. **Given** 분석 탭에 처음 진입했을 때, **When** 채팅창을 보면, **Then** AI 가 보낸 형태의 환영 메시지가 아기 이름이 채워진 채 이미 도착해 있다(예: "물결이에 대해 궁금한 건 무엇이든지 물어보세요…").
2. **Given** 보호자가 질문을 입력하고 전송하면, **When** 답변이 생성되면, **Then** 답변은 토큰 단위로 점진 표시(스트리밍)되며, 해당 아기의 월령·최근 기록에 근거한 내용을 담는다.
3. **Given** AI 응답이 스트리밍되는 중일 때, **When** 사용자가 추가 입력을 시도하면, **Then** 전송은 잠겨(전송 버튼 비활성) 있고 입력창 타이핑만 허용된다.
4. **Given** 기록이 거의 없는 아기일 때, **When** 질문하면, **Then** 오류 없이 "기록이 부족해 일반적 안내" 형태의 답변을 받는다(기록 부재는 오류가 아니다).
5. **Given** 다른 아기로 전환했을 때, **When** 채팅창을 보면, **Then** 새 아기 기준의 환영 메시지·세션·내역으로 갱신된다(아기별 분리).

---

### User Story 2 — 궁금증 추천(랜덤) 질문 (Priority: P2)

무엇을 물어야 할지 막막한 보호자로서, 나는 입력창의 버튼을 눌러 "부모가 궁금해할 만한 질문" 을 추천받고, 마음에 들면 그대로 보내거나 다듬어 보내고 싶다.

상단 입력 영역에는 새로고침 형태의 버튼이 있고, 누를 때마다 추천 질문이 바뀐다(suno 온보딩 방식). 추천 질문은 **세션 시작 시 LLM 이 그 아기의 기록·월령을 반영해 5개를 생성**해 두고, 버튼은 그 풀을 로컬에서 순환 노출한다.

**Why this priority**: P1 이 "질문에 답한다" 는 가치라면, P2 는 "질문 자체를 떠올려 준다" 는 진입 장벽 완화 가치다. P1 없이는 성립하지 않지만, 빈 채팅창 앞에서의 막막함을 줄여 사용을 유도한다.

**Independent Test**: 세션 진입 후 추천 버튼을 반복해 눌러 질문 후보가 순환 노출되는지, 노출된 질문을 탭하면 입력창에 채워지는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 세션이 시작됐을 때, **When** 입력 영역을 보면, **Then** 추천 질문 1개가 노출되고 새로고침 버튼이 함께 있다.
2. **Given** 추천 질문이 노출돼 있을 때, **When** 새로고침 버튼을 누르면, **Then** 미리 생성된 풀에서 다음 후보로 바뀐다(추가 네트워크 호출 없음).
3. **Given** 추천 질문이 노출돼 있을 때, **When** 그 질문을 탭하면, **Then** 입력창에 해당 문구가 채워지고 사용자가 그대로 전송하거나 수정할 수 있다.
4. **Given** 추천 질문 생성이 실패했을 때(네트워크 등), **When** 입력 영역을 보면, **Then** 채팅 자체는 정상 동작하고 추천만 비노출된다(추천은 보조 기능).

---

### User Story 3 — 세션 전환과 지난 대화 내역 (Priority: P2)

여러 번 상담해 온 보호자로서, 나는 시계 아이콘으로 지난 대화 내역을 열어 예전 상담을 다시 보고, 필요하면 그 대화를 이어서 계속하고 싶다.

채팅창 상단의 시계 아이콘 버튼을 누르면 바텀시트로 **지난 대화 내역 리스트**가 뜬다. 앱을 완전히 종료했다 다시 켜면(프로세스 콜드 스타트) 새 대화 세션이 시작되고, 직전 세션은 내역 리스트로 들어간다. 내역에서 하나를 선택하면 분석 탭 채팅창에 그 지난 대화가 떠 **현재 활성 세션**이 되고, 그때까지 진행 중이던 대화는 내역 리스트로 이동한다.

**Why this priority**: P1/P2(추천) 가 "이번 상담" 의 가치라면, 본 스토리는 "지난 상담의 연속성" 가치다. 단발 상담으로도 가치가 있으나, 내역이 누적되면 재방문 가치가 커진다.

**Independent Test**: 한 세션에서 메시지를 주고받은 뒤 앱을 콜드 스타트해 새 세션을 만들고, 시계 버튼으로 직전 세션이 내역에 있는지, 선택 시 그 대화가 채팅창에 뜨고 이어서 입력 가능한지 확인한다.

**Acceptance Scenarios**:

1. **Given** 한 세션에서 메시지를 주고받았을 때, **When** 앱을 완전히 종료 후 재실행해 분석 탭에 진입하면, **Then** 빈 새 세션(환영 메시지)이 시작되고 직전 세션은 내역에 들어간다.
2. **Given** 사용자가 메시지를 하나도 보내지 않은 세션일 때(환영만 보고 떠남), **When** 새 세션이 시작되면, **Then** 그 빈 세션은 내역 리스트에 남지 않는다.
3. **Given** 시계 버튼을 눌렀을 때, **When** 바텀시트를 보면, **Then** 그 아기의 지난 대화들이 "첫 사용자 메시지 + 시각" 형태로 최신순 정렬되어 표시된다.
4. **Given** 진행 중인 대화가 있을 때, **When** 내역에서 다른 대화를 선택하면, **Then** 채팅창에 선택한 지난 대화가 활성 세션으로 뜨고, 진행 중이던 대화는 내역 리스트로 이동하며, 이어서 입력할 수 있다.

---

### Edge Cases

- 완성된 기록이 거의/전혀 없는 아기 → 오류가 아니라 "기록 부족" 을 전제한 일반적 답변을 생성한다(기록 부재는 정상 상태).
- 출생 정보(`birthDate`)가 없어 월령을 산출할 수 없을 때 → 월령 의존 진단을 생략하고 가능한 범위에서 답하되, **답변 말미에 "출생일 정보를 입력하면 월령에 맞는 답변을 받을 수 있다" 는 안내를 덧붙인다**(FR-036).
- AI 응답 스트리밍 도중 네트워크/서버 오류로 끊기면 → 부분 스트림은 폐기하고, 해당 사용자 질문 자리에 에러 버블 + "다시 시도" 를 표시한다(같은 질문 재전송).
- 추천 질문 생성 실패 → 채팅은 정상, 추천 영역만 비노출(추천은 보조 기능).
- 오프라인/네트워크 불가 → 신규 전송은 비활성(networkError 안내)하되, 이미 서버에 저장된 과거 대화는 캐시 범위 내에서 열람 가능.
- 빈 입력/공백만 입력 → 전송 비활성(유효 텍스트 없으면 보낼 수 없음).
- AI 응답이 진행 중일 때 추가 전송 시도 → 전송 잠금(전송 버튼 비활성), 입력창 타이핑은 허용.
- 입력이 글자수 상한을 초과 → 상한까지만 허용(초과 입력 차단)하고 남은 글자수를 안내.
- 매우 긴 세션 → LLM 전송 컨텍스트는 최근 N턴 윈도우로 제한한다(전체 대화를 매번 보내지 않는다).
- 내역에서 대화를 선택하는 순간 진행 중 세션이 비어 있으면(사용자 메시지 0) → 그 빈 세션은 내역에 추가하지 않고 폐기한다.
- 아기 전환 → 채팅 세션·내역·추천은 모두 새 아기 기준으로 갱신된다(아기 간 대화는 섞이지 않는다).

## Requirements *(mandatory)*

### Functional Requirements

#### 채팅 표시·입력 (Presentation 관심사)

- **FR-001**: 시스템은 분석 탭 진입 시 요약 카드 4개 아래에 채팅창을 표시해야 한다(요약은 별도 feature, 본 spec 은 채팅창만 책임).
- **FR-002**: 시스템은 새 세션 시작 시(첫 진입 포함) AI 가 보낸 형태의 **환영 메시지**를 채팅창에 표시해야 한다. 메시지는 아기 이름이 채워진 고정 문구이며, 실제 LLM 호출 없이 **클라이언트가 표시 전용으로 생성**한다(저장하지 않는다).
- **FR-003**: 시스템은 사용자가 입력한 유효 텍스트(공백 제외 1자 이상)에 한해 전송을 허용해야 한다. 빈/공백 입력은 전송할 수 없다.
- **FR-004**: 시스템은 AI 응답을 **토큰 단위 스트리밍**으로 점진 표시해야 한다.
- **FR-005**: 시스템은 AI 응답이 진행 중인 동안 **추가 전송을 잠가야** 한다(전송 버튼 비활성). 입력창 타이핑은 허용한다(단일 진행 보장).
- **FR-006**: 시스템은 시각 표시를 사용자의 로컬 타임존 기준으로 보여줘야 한다(도메인 시각은 UTC).
- **FR-007**: 사용자가 아기를 전환하면 시스템은 채팅 세션·내역·추천을 새 아기 기준으로 갱신해야 한다.
- **FR-008**: 시스템은 사용자 메시지를 **optimistic** 으로 즉시 표시한 뒤 전송하고, assistant 응답은 스트리밍 완료 시 서버 저장으로 확정해야 한다.

#### 추천 질문 (Presentation 관심사)

- **FR-010**: 시스템은 세션 시작 시 그 아기의 기록·월령을 반영한 추천 질문 **5개**를 LLM 으로 1회 생성해 보유해야 한다.
- **FR-011**: 입력 영역의 새로고침 버튼은 **보유한 추천 풀을 로컬에서 순환** 노출해야 한다(버튼 탭마다 추가 네트워크 호출 없음).
- **FR-012**: 노출된 추천 질문을 탭하면 입력창에 해당 문구가 채워지고, 사용자가 그대로 전송하거나 수정할 수 있어야 한다.
- **FR-013**: 추천 질문 생성이 실패하면 채팅 본 기능은 정상 동작하고, 추천 영역만 비노출되어야 한다(추천은 보조 기능, 실패가 채팅을 막지 않는다).

#### 세션 수명주기·내역 (조회/저장 계약 + Presentation)

- **FR-020**: 시스템은 **프로세스 콜드 스타트** 시 새 채팅 세션을 시작해야 한다. 백그라운드→포그라운드 복귀(resume)는 기존 세션을 유지한다(세션 경계 = 콜드 스타트).
- **FR-021**: 시스템은 사용자 메시지가 **1건 이상인 세션만** 지난 대화 내역에 포함해야 한다. 환영만 보고 떠난 빈 세션은 내역에 남기지 않는다.
- **FR-022**: 시스템은 시계 아이콘 버튼으로 지난 대화 내역을 바텀시트로 표시해야 하며, 각 항목은 **첫 사용자 메시지 + 마지막 활동 시각**으로 식별되고 최신순 정렬되어야 한다.
- **FR-023**: 사용자가 내역에서 한 대화를 선택하면 시스템은 그 대화를 **현재 활성 세션**으로 채팅창에 표시하고, 그때까지 진행 중이던 세션을 내역으로 이동시켜야 한다. 선택한 지난 대화는 **이어서 입력 가능**해야 한다.
- **FR-024**: 채팅 세션·메시지·내역은 모두 **특정 아기(`babyId`)에 귀속**되며, 다른 아기의 대화와 섞이지 않아야 한다.
- **FR-025**: 시스템은 "현재 활성 세션 식별자" 만 로컬에 보관하고, 대화·메시지 본문은 서버(원격)에 저장된 것을 단일 진실로 삼아야 한다(SSOT 는 서버).

#### LLM 응답 비즈니스 규칙 (집계 주체 비종속, SSOT)

> 아래는 "무엇이 올바른 입력/제약인가" 의 정의다. 실제 컨텍스트 조립·프롬프트 구성·모델 호출을 어디서 하는지는 plan 에서 결정한다([constitution Principle IV](../constitution.md)). 답변의 자연어 품질 자체는 모델 책임이며 결정론적으로 명세하지 않는다 — 본 spec 은 **답변이 근거로 삼는 입력의 범위와 제약**을 고정한다.

- **FR-030**: LLM 에 전달하는 아기 컨텍스트는 **(a) 요약 4지표(분석 요약 feature 산출물) + (b) 최근 N일 원본 기록 + (c) 비교 기준 월령(미숙아는 교정연령)** 으로 구성해야 한다. 컨텍스트 윈도우 일수(N)는 plan 에서 확정하고 운영자가 조정 가능해야 한다.
- **FR-031**: 요약 지표의 정의·계산 규칙은 [`analytics_summary.md`](./analytics_summary.md) FR-010~FR-019 를 SSOT 로 재사용한다(본 spec 은 중복 정의하지 않는다).
- **FR-032**: 1회 전송 시 LLM 에 보내는 대화 이력은 **최근 N턴 윈도우**로 제한해야 한다(전체 세션을 매번 보내지 않는다). 윈도우 크기는 plan 에서 확정한다.
- **FR-033**: 한 번에 입력 가능한 사용자 메시지 길이는 **글자수 상한**(plan 확정, 기본 1000자)을 가져야 한다. 상한 초과 입력은 차단한다.
- **FR-034**: 기록이 부족하거나 출생 정보가 없어 일부 컨텍스트가 비어도 **오류가 아니다.** 가능한 범위의 컨텍스트로 답변을 생성한다.
- **FR-035**: LLM API 키 등 비밀값은 **클라이언트에 노출되지 않아야** 한다(호출은 서버 경유). 모델 식별자는 운영자가 설정으로 교체 가능해야 한다.
- **FR-036**: 아기의 출생 정보(`birthDate`)가 없어 월령을 산출할 수 없는 경우, 프롬프트 정책은 답변 말미에 **"출생일 정보를 입력하면 월령에 맞는 답변을 받을 수 있다" 는 안내**를 포함하도록 지시해야 한다. 출생 정보가 있으면 이 안내는 붙지 않는다.

#### 조회·저장 계약

- **FR-040**: 시스템은 한 세션의 메시지 목록, 그리고 한 아기의 대화 세션 목록(내역)을 조회할 수 있어야 한다.
- **FR-041**: 시스템은 메시지 전송 시 사용자 메시지와 assistant 응답을 서버에 저장해야 한다. assistant 응답은 스트리밍 완료 시점에 확정 저장한다.
- **FR-042**: 시스템은 인증되지 않은 요청, 접근 불가/미존재 대화·아기, 네트워크 실패, 응답 해석/스트림 실패를 서로 구분되는 오류 상태로 호출자에게 전달해야 한다.
- **FR-043**: 시스템은 기록이 전혀 없는 아기, 메시지가 없는 신규 세션에 대해서도 오류 없이 정상(빈) 상태를 반환해야 한다.

### Key Entities

- **대화 세션 (Conversation/Session)**: 한 아기에 대한, 한 번의 연속된 상담 단위. `babyId` 에 귀속되며 콜드 스타트로 새로 시작된다. 사용자 메시지 1건 이상일 때만 내역에 노출된다. 식별 표시는 "첫 사용자 메시지 + 마지막 활동 시각".
- **메시지 (Message)**: 한 세션 안의 한 발화. 역할(`user` | `assistant`), 본문 텍스트, 생성 시각(UTC)을 가진다. 환영 메시지는 표시 전용이며 엔티티로 저장되지 않는다.
- **추천 질문 (Suggested Question)**: 세션 시작 시 그 아기 기준으로 생성된 질문 후보(5개). 표시용 풀이며 영속 저장 대상이 아니다(세션 한정).
- **아기 컨텍스트 (Baby Context)**: LLM 에 주입되는 입력 묶음 — 요약 4지표 + 최근 N일 원본 기록 + 비교 기준 월령. 분석 요약 feature 및 기록 도메인 모델을 재사용한다.
- **현재 활성 세션 포인터 (Active Session Pointer)**: 아기별로 "지금 채팅창에 떠 있는 세션" 식별자. 로컬에 보관하는 유일한 채팅 영속 상태(본문은 서버 SSOT).

### Assumptions

- **아기 등록·선택은 본 spec 밖에서 이미 끝나 있다**: 진입 시점에 유효한 "현재 선택된 아기" 식별자(`CurrentBabyController`)가 존재한다고 전제한다. 본 spec 은 그 결과만 입력으로 받는다.
- **인증된 사용자 세션이 이미 존재한다**: 진입 시점에 사용자가 인증되어 있다고 전제한다. 인증·세션 수명 관리는 기존 인증 모듈 책임이며, 미인증/만료 진입은 FR-042 의 오류 구분으로만 다룬다.
- **요약 지표는 분석 요약 feature 가 제공한다**: 채팅 컨텍스트의 일부인 4지표는 [`analytics_summary.md`](./analytics_summary.md) 의 산출물을 재사용한다. 그 계산 규칙은 해당 spec 이 SSOT 다(FR-031).
- **기록 도메인 모델 정의가 안정적이다**: 컨텍스트로 쓰는 원본 기록 모델(`CareRecord`/`RecordDetailData`/`RecordType` 등)을 기존 정의 그대로 재사용한다. 이 모델이 바뀌면 컨텍스트 구성에 영향을 줄 수 있음을 전제한다.
- **LLM 호출은 서버(원격)가 대행한다**: API 키 보관·모델 호출·프롬프트 조립은 서버(백엔드) 책임이다(FR-035). 본 spec 은 클라이언트가 그 결과(스트림/저장)를 받는다는 계약만 전제한다.
- **답변의 의학적 정확성/안전성은 모델·프롬프트 정책의 책임이다**: 본 spec 은 답변 입력 범위와 제약(FR-030~FR-035)만 고정하고, 답변 문장 자체의 정합성은 결정론적으로 명세하지 않는다. 의료 자문 면책·안전 가드레일 문구는 plan 의 프롬프트 정책에서 다룬다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 기록이 있는 아기에서 질문 전송 후 **첫 토큰이 3초 이내** 에 스트리밍되기 시작한다.
- **SC-002**: 기록이 충분한 아기에 대한 답변은 그 아기의 월령/최근 기록에 부합하는 **구체적 근거**(일반론이 아닌)를 포함한다(질적 평가 기준, 샘플 시나리오로 검증).
- **SC-003**: 기록이 전혀 없거나 부족한 경우에도 채팅이 오류 화면 없이 정상 답변(일반 안내)을 **100% 반환** 한다.
- **SC-004**: 콜드 스타트 후 첫 진입에서 새 빈 세션이 시작되고, 직전 세션(사용자 메시지 1건 이상)이 내역에 **누락 없이** 나타난다.
- **SC-005**: 내역에서 지난 대화를 선택하면 그 대화가 활성 세션으로 떠 이어서 입력 가능하고, 직전 진행 세션은 내역으로 이동한다(데이터 유실 0).
- **SC-006**: LLM API 키가 클라이언트 빌드 산출물/네트워크 트래픽에서 **노출되지 않는다**(서버 경유 100%).
